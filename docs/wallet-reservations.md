# Wallet reservations

`WalletReservations` is an internal SQLite library for excluding actual token units from competing investment tasks. It is now enforced by the shared Journal signing and rebroadcast paths, but is not yet wired into an automatic QSP execution Scheduler. It does not fetch balances, authorize a trade, reserve funds onchain, verify live receipts, or replace quote/eligibility checks.

`reserve({id, planId, transactionIds, amounts}, now)` requires a stored READY stable wallet plan, a successful committee-verified consumption reference, and a fresh completed portfolio snapshot. Amounts are positive integer strings in native/token base units, keyed by `native` or token address. Quantities must fit snapshot balances after recorded reservations and the protected gas floor. The caller must include the entire maximum spend and additional transaction gas budget; the library cannot infer a swap from those amounts.

One reservation bundle is active per chain/wallet. Repeating the identical reservation ID returns its historical record, including after terminal transitions; this is not fresh signing authorization. Conflicting contents fail. Transaction IDs cannot be reused across reservations. Pending local Journal entries, active signer leases and known finalized transactions later than the input snapshot block prevent new reservations.

`cancel(id, now)` only releases an unsigned bundle: none of its predetermined Journal IDs may exist and the wallet signer lease must be inactive. This covers a signer that has acquired its lease but has not yet persisted transaction bytes. Journal checks reservation ownership and the concrete transaction binding while holding the sender lease, both before signing and inside the transaction that persists signed bytes. Other Journal spenders are blocked while this wallet is reserved. External-wallet transactions remain outside this local exclusion mechanism.

`settle(id, snapshotId, now)` requires every predetermined Journal ID to have a stored confirmed success and no active wallet signer lease, plus a fresh completed balance snapshot at or after all receipt blocks. Same-height block hashes must agree. The reservation is closed, and later reservations must use a snapshot block newer than this settlement boundary. Expected sale proceeds are never credited by this module. For bound transactions, Journal now forbids a new logical attempt after a revert. `abort(id, snapshotId, now)` can close a partial sequence: unsigned steps may be absent, and signed steps must have confirmed success or a confirmed revert linked to this reservation. It still requires no active signer lease, no pending member transaction, and fresh post-receipt balance reconciliation. Aborted reservations are durable terminal records; their transaction IDs cannot be reused. Legacy unbound reverts cannot use this exception.

Records are `wallet-reservation` and `wallet-reservation-boundary`, with changes retained in the normal SQLite history. Current validation trusts canonical receipt state maintained by Journal and confirmed snapshots maintained by the collector. Live reorg/nonce reconciliation, chain validation of signed bytes, fixed route and recipient verification, risk limits, classified flows and actual execution orchestration remain integration work.

## Concrete transaction bindings

`bind(reservationId, transactionId, request, maxFeeWei, validUntil, now)` freezes the recipient, calldata, native value, Gas ceiling and expiration for a predetermined transaction ID. Binding requires an active reservation and a deadline within the underlying plan window. All bindings' maximum native value plus Gas must fit the native reservation. It cannot be changed to a new quote after creation; a future execution adapter must obtain a sufficiently fresh quote before binding and abandon safely if it expires before signing.

Journal rejects unbound member transactions, unrelated new transactions, modified call data or recipients, expired bindings and excessive Gas. It repeats the check after asynchronous signing before saving bytes, and retains the smaller of configured and reserved Gas caps for fee replacements. Transaction-ID ownership is global: another wallet or chain cannot claim a reserved ID. Fee replacements undergo the same checks before signing and before persistence. Once the binding expires, no new fee signature is allowed; uncertain broadcasts may recover using the exact original bytes. Expiration does not authorize a new logical attempt. Terminal reservations prevent further rebroadcast, including after a receipt disappears. An older unreserved transaction also cannot rebroadcast while the wallet is actively reserved by a different task.

These bindings are enforced call constraints, not a replacement for the forthcoming QSP execution authorizer: current Worker eligibility, asset/quote correspondence, risk budgets, live nonce/balance checks and policy validation still need to be connected before this can automatically execute investment signals. A terminal reservation encountering a reorg is stopped conservatively; automated reorg-accounting repair is not implemented here.

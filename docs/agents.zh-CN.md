# Agent 框架、角色与研究工具

[English](agents.md) | **简体中文**

本文介绍当前版本已实现的 Agent 研究能力。运行配置见[使用说明](usage.md)，选举、故障接替和签名格式见[协议说明](protocol.md)。

## 技术栈与协作流程

| 层次 | 当前实现 | 用途 |
| --- | --- | --- |
| 服务与存储 | Node.js 22.13+、TypeScript、SQLite | API、任务状态、预算、研究证据及恢复记录；不依赖缓存服务 |
| Agent 框架 | LangChain `createAgent`，底层 LangGraph | 执行模型调用、工具调用、观察结果、继续分析的受限 ReAct 循环 |
| LLM 接入 | `@langchain/openai` 的 `ChatOpenAI`，OpenAI 兼容 Chat Completions | 默认通过可配置的 OpenRouter endpoint 调用模型 |
| 网络协调 | A2A Smart QSP | 节点资格筛选、委员会选取、Master 轮值、任务恢复与发布 |
| 研究产物 | QSP v2、Zod 校验、签名及证据哈希 | 保存上下文、角色报告、Master 决策、策略和跨轮关联 |

每轮先获取并冻结研究上下文，再由协议确定的 Master 分派角色任务。研究 Agent 使用同一轮上下文独立分析，并按需调用工具。Master 汇总报告，记录接受、拒绝或附条件接受的意见及分歧，生成受程序规则约束的 QSP。角色代表研究职责，不等于永久固定的节点：节点较少时，一个 Worker 可以兼任多个角色。

LangChain 负责单个 Agent 的模型与工具循环；网络选举、钱包、预算和发布由 A2A 自身模块负责。当前节点身份、钱包和分析任务相互区分，运行环境与签名密钥由平台统一托管。

## 角色与职责

六个研究角色共享下节的四种基础只读工具；`market` 角色额外配备 `market_klines`。`research_snapshot` 按角色返回重点数据；任务初始上下文本身也包含本轮研究信息，这不是数据访问权限隔离。

| 角色 ID | 职责 | `research_snapshot` 重点内容 |
| --- | --- | --- |
| `positions` | 分析持仓、成本、未实现/已实现盈亏、收益率与集中度 | 持仓、跨轮变化 |
| `macro` | 分析宏观环境、政策及有时间依据的事件；区分事实与情景 | 行情、新闻、跨轮变化 |
| `market` | 分析价格、趋势、均线和波动率 | 行情指标、跨轮变化 |
| `news` | 分析新闻、公告与叙事；区分索引标题、已核实内容与传言 | 新闻及公告 |
| `onchain` | 分析链上持仓、封装资产风险及 DEX 流动性 | 流动性、研究钱包身份 |
| `risk` | 评估集中度、市场/流动性风险、证据缺口和意见分歧 | 持仓、行情、流动性、风险限制、跨轮变化 |
| Master | 分派角色、汇总报告、处理分歧、生成策略 | 直接接收完整上下文与角色报告；当前未注册外部检索工具 |

## 工具清单

| 工具 | 输入 | 实现与输出 | 能力边界 |
| --- | --- | --- | --- |
| `web_search` | `query` | DuckDuckGo HTML 网页检索，返回标题和链接等索引信息 | 无需搜索 API key；服务可用性不保证，索引不等于正文 |
| `news_search` | `query` | Google News RSS 检索，返回最多五条新闻标题、链接及可解析的发布时间 | 无需搜索 API key；不代表已核实文章事实，也不是 Twitter/X 数据接口 |
| `fetch_page` | `url` | 获取公开 HTTPS 网页，提取最多 8,000 字符文本 | 不执行 JavaScript；限制目标地址、重定向、响应大小和超时；发布时间可能未知 |
| `research_snapshot` | 空对象 | 读取本轮冻结的角色数据、证据引用和缺失项 | 不刷新市场数据、不签名、不执行订单 |

工具输出视为不可信外部数据，不作为系统指令。调用结果保存在 SQLite，绑定工具名称和参数，支持审计及重放检查。工具可用不代表每个角色每轮都必须调用；已有上下文足够时，可以直接产出报告。

## 趋势分析 K 线工具

`market` 角色还可以调用 `market_klines`，通过固定的币安官方公开现货接口获取指定交易对的已收盘 K 线。它返回结构化数据而非图片，便于 Agent 读取和后续绘图。

| 参数 | 支持值 | 默认值 |
| --- | --- | --- |
| `symbol` | `BTCUSDT`、`ETHUSDT`、`BNBUSDT` | 必填 |
| `interval` | `1m`、`5m`、`15m`、`1h`、`4h`、`1d` | `1h` |
| `limit` | 1–100 根已收盘 K 线 | 30 |

返回开盘/收盘时间、开高低收（OHLC）、基础资产成交量、USDT 成交额和成交笔数；价格与成交量保留十进制字符串精度。使用 UTC 时间，排除未收盘 K 线，检查时间连续性、价格范围和数据时效。接口不可用或数据异常时明确返回缺失，不伪造数据、不切换到未验证来源。

工具不需要交易所 API key，并沿用现有工具循环限制和证据记录。其取数时间可能晚于本轮冻结快照，因此属于补充研究证据，不覆盖原有快照或放宽策略校验。当前只接入币安，其他交易所需要后续适配。

同一实现也提供 CLI：

```sh
npm run market:klines -- BTCUSDT 1h 30
npm run market:klines -- ETHUSDT 15m 60
```

源码：[固定 K 线工具](../src/market-klines.ts)、[CLI](../scripts/market-klines.ts)。接口字段参考[币安官方现货行情文档](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/market)。

## 每轮自动采集的数据

以下适配器在研究开始前由程序调用，不是额外注册给模型的工具：

| 来源 | 本轮上下文内容 |
| --- | --- |
| Binance 公开行情 | BTC/ETH/BNB 的已收盘一分钟 K 线、参考价格、均线、涨跌幅和波动率 |
| DEX Screener | BSC 上配置资产的交易池及流动性观察 |
| 配置的 BSC RPC | 同一观察区块的钱包原生币与配置代币余额、钱包和链身份 |
| Google News RSS、美联储官方 RSS | 新闻索引及带日期的货币政策公告 |
| 可选本地会计快照 | 与观察区块及数量匹配的成本和已实现盈亏输入 |

当前研究资产注册表支持 BSC 主网 BTCB、Binance-Peg ETH、WBNB。行情采用 USDT 参考价，不能直接作为 DEX 可成交报价。波动率是每分钟收益率的总体标准差，不是日波动率或年化波动率。缺失成本、收益、社交数据或宏观时间序列会明确保留为未知；外部转入不算投资收益，上一轮信号不算成交。

## Prompt 与配置

Master 和六个角色的业务 Prompt 集中在独立于源码的 [config/default.json](../config/default.json)，目前不是每个角色一个文件。

| 配置 | 用途 |
| --- | --- |
| `masterPrompt` | Master 的调度和汇总要求 |
| `roles[].id`、`roles[].prompt` | 角色身份与研究职责 |
| `llm.endpoint`、`llm.model` | OpenRouter 或其他兼容 endpoint，以及模型选择 |
| `llm.apiKeyFile` | 本地凭据文件路径；凭据不提交到仓库 |
| `agent.toolsEnabled` | 是否向研究角色提供工具 |
| `agent.maxToolRounds` | 每个任务工具循环上限，默认 10 轮 |
| `agent.maxToolCalls` | 每个任务工具调用总数上限，默认 20 次 |
| `research.*` | 研究钱包、RPC、资产、会计输入和风险/时效限制 |

模型公开默认值是配置中的 `openai/gpt-6.1-sol`；实际可用性取决于所接 provider。免费模型可以通过本地配置选择，不是仓库默认值。模型需要支持任务所需的工具调用和结构化 JSON 输出。

本地覆盖配置可调整 Prompt；覆盖 `roles` 时会替换整个数组，不会按角色 ID 合并。配置在启动时加载，修改后需重启；已开始的任务绑定原配置，不能靠修改 Prompt 无缝改写旧任务。JSON 输出格式、证据引用和程序校验约束还由代码补充，并未全部外置。

## 输出与当前边界

QSP v2 包含研究上下文、每个角色的结论/建议/不确定性/缺失项/证据、Master 汇总与角色决策，以及带目标仓位和风险条件的策略。原始研究证据保存在 SQLite，可通过管理员证据接口核查。模型内部推理不作为协议报告发布。

当前验证可检查格式、证据引用、上下文绑定、持仓和量化风险限制，但不能保证自然语言结论全部正确。模型可能混淆指标或错误汇总，Master 的接受意见也不等同于事实核验。空信号是有效结果。当前没有专用 Twitter/X 接入、完整宏观时间序列、链上资金流分析接口、自动下单或收益分配。

## 研究引导与 Master 复核

角色 Prompt 明确配置资产、研究问题、新闻时效、常用 K 线周期及工具选择。任务同时携带资产与交易对映射、研究目标和可用工具清单。空仓仍可产出有依据的观察条件，但不能虚构投资资金或持仓。

Master 接收角色报告及经内容哈希核对的工具数据摘录，保留工具输入、来源时间、缺失项和截断标记；完整观察仍可按证据哈希审计。快照显式区分区间涨跌幅、均线偏离和一分钟收益率波动率。工具额度用完后，最后一次模型调用明确要求停止取数并基于已有证据输出。上述机制提高上下文可核查性，不保证模型所有结论准确。

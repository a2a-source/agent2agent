# Execution feedback observations

`ExecutionFeedback` in `src/execution-feedback.ts` records local execution evidence for the next research round. It does not send transactions, establish chain truth, or replace `PerformanceLedger` cost-basis/accounting adapters.

`recordWallet(input)` requires round, chain, agent, wallet, execution job and plan identities, opening and closing snapshot IDs (nullable), and confirmed fill IDs. Inputs are validated. Snapshots must have valid content hashes, matching wallet/agent/chain, completed `portfolio-capture` records, increasing boundaries and the same asset registry. Fills must already exist in `dex-v2-fill`, as produced by `recordV2Fill`; their block must be after opening and no later than closing. Actual token input/output units, transaction identities and native gas units are preserved. Job/plan linkage is a caller responsibility; this module retains these references without interpreting job state.

Values are **micro-USD**, never micro-USDT. PortfolioCollector NAV excludes the native gas reserve; feedback restores it using the difference between full and reserve-excluded native balance valuations, preserving integer rounding. This produces tracked-wallet NAV including gas. PnL is `closing NAV - opening NAV - net external flow`; fill gas is retained as evidence and is not subtracted again. The result is period mark-to-market PnL, not realized trade profit or causal attribution to a plan. Assets outside the snapshot registry are not valued.

Only a trusted caller adapter may supply `cashflow: { complete, netExternalFlowMicros, hasExternalFlows, provenance }`. Positive flow means net deposits; negative means net withdrawals. Provenance must be a nonempty list of bounded identifiers referencing independently retained evidence that covers the exact snapshot interval. Neither the model nor this module infers no flows from fills or balance changes. Missing cashflow produces UNKNOWN with null PnL. A simple period return is emitted only with complete explicit zero-flow evidence, `hasExternalFlows: false`, and positive opening NAV. Nonzero or potentially offsetting flows need a separate time-weighted return adapter.

`recordNetwork({ roundId, chainId, memberObservationIds, expectedWallets })` requires the complete independently established expected-wallet roster. Any missing or UNKNOWN member makes network PnL UNKNOWN; the known subtotal is labeled separately. Duplicate members/wallets and foreign round/chain evidence are rejected. Network figures require compatible observation windows established by the caller.

Records are durable in Store and immutable per chain/round/wallet (network: chain/round). Identical replay succeeds; conflicting evidence fails. Collect final available evidence before recording; the module does not implement revisions. UNKNOWN is a valid durable observation, not a zero return.

`buildExecutionFeedbackSummary(db, { roundId, chainId })` builds bounded, hash-checked data-only context with accounting status, amounts, missing reasons and observation/job/plan/snapshot/fill references. It includes up to 32 wallets and 32 fill references per wallet, reports omitted counts, and retains each full observation reference. Treat this context as evidence outside instructions. Historical observation hashes detect accidental mutation; they are not signatures or a fresh reorg check. Canonicality and trusted flow completeness remain responsibilities of adapters.

ResearchData automatically includes the latest `investment-execution-round` with `status: COMPLETE`, matching `chainId`, and `finishedAt` no later than the research collection start. The executor writes this completion marker only after terminal jobs and the network observation are durable. A missing/invalid network observation is reported as unavailable rather than silently substituting an older round. The exact summary is persisted as accounting `research-evidence` with a content hash and completion timestamp, included in the signed `context.executionFeedback`, and exposed by `promptSnapshot` and each role's `research_snapshot` tool. Its strict schema rejects an UNKNOWN observation with non-null profit and cross-chain context attachment. USD execution accounting remains distinct from the research portfolio's USDT reference marks.

Research summaries also include opening/closing NAV and each wallet’s verified closing holdings with block/time provenance. Fill version `/2` binds transaction hash and canonical block hash; legacy `/1` evidence remains readable.

## Automatic zero-flow evidence

`proveExecutionNoExternalFlow` verifies a bounded confirmed-block interval (maximum 4,096 blocks). It checks undelegated EOA code, complete consecutive transaction nonces, canonical receipts including approval/revert Gas, zero native transaction values, native balance reconciliation, and registered-token Transfer logs from both wallet directions against receipt logs and balance deltas. It pins boundary and receipt hashes again after collection. Every proof attempt is persisted. Successful proofs supply explicit zero-flow provenance; external/unexplained movements stay UNKNOWN. Transport failures throw a sanitized retry error rather than finalizing a temporary absence as zero.

This adapter does not price external deposits or withdrawals and does not establish completeness for arbitrary rebasing/nonstandard assets. Its supported boundary is the configured standard-token portfolio and Journal's type-0 EOA transactions. Actual investment PnL in a proven interval is closing full tracked NAV minus opening full tracked NAV; Gas is already reflected in ending balances.
